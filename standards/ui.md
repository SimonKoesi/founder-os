# UI behavior

Inspect the existing framework and widgets before changing UI. Choose only useful
contracts from [components](ui-components.md); charts use [charts](charts.md).
If `ui-bausteine` is installed, use it for implementation and flow verification;
otherwise apply these portable contracts with existing native controls.
Keep calm surfaces, alignment, a targeted accent and at most one emphasized main
action per view. No decorative introductions. Provide visible labels, focus,
contrast and selection indicators beyond color. Handle narrow layouts and large text.
Actions need real routing, state, validation and persistence where applicable.
Test input retention on errors, cancellation, retry, back route and direct entry.
Animations honor reduced motion; transparency needs an opaque fallback. Project
design constraints and accessibility prevail over optional stylistic examples.
