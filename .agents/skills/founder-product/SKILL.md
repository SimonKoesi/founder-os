# founder-product

Use the user's project working directory. Inputs: project context, state, existing
artifacts and the requested outcome. Missing blocking evidence stays explicit.

Read current requirements and real user evidence. Separate outcomes from implementation assumptions. Define the complete first flow, failure/cancel/retry behavior and measurable acceptance. Use project type and size to choose process depth.

Read [workflow](../../../workflows/definition.md) and
[quality](../../../standards/quality.md) as relevant. Follow current authorization;
this skill grants no additional permissions or agent delegation.

Expected result: context with problem, users, scope and acceptance; roadmap and task IDs. Save enduring decisions and actual checks in project
context/state/handoff; keep temporary diagnostics out of long-term context.
