# Seven operating examples

These are synthetic work instructions, not completed customer projects.
Executable acceptance cases are in `tests/test_framework.py`.

| Scenario | Example instruction | Context, route and useful outcome |
| --- | --- | --- |
| Business idea | Prüfe eine Reparaturvermittlung für lokale Fahrradhändler. | idea profile; discovery then validation; three lenses, unknown pricing recorded, real pilot with success threshold |
| SaaS | Definiere den ersten Ablauf einer Terminverwaltung für mehrere Unternehmen. | saas profile; product/architecture/build; tenant boundaries, acceptance and idempotent subscription events |
| Automation | Erstelle eine lokale CSV-Prüfung ohne externe Uploads. | automation profile; definition/build/test; dry run, malformed input, repeated trigger and unchanged source |
| Existing repository | Übernimm diese Anwendung und finde ihre realen Start-/Testbefehle. | adopt; preserve code/rules; discovery and evidence-based context, no invented architecture |
| New session | Setze die nächste belegte Aufgabe fort. | founder-context; pin check, context/state/handoff, actual tree inspection and relevant route |
| Framework update | Zeige den Wechsel auf die neue zentrale Installation. | framework skill; update preview, reviewed changed rules, explicit apply and recoverable prior pin |
| Bugfix | Beim erneuten Speichern einer ungültigen Panelantwort geht die alte verloren. | bugfix/build; regression preserves valid answer, validates before replace and verifies success path |

Minimum context on entry: local instructions and four persistent entry files, then
only selected central modules. A new business does not require all eleven business
methods; a software bug does not restart strategy or marketing. Stop only dependent
work when evidence or authorization is missing, and preserve an actionable handoff.
