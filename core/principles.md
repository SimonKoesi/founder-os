# Principles

One owner per fact: project goals in context, phase and tasks in state, rationale
in decisions, session continuation in handoff. Link instead of copying.
The framework holds reusable policy; projects hold evidence and exceptions.
Prefer existing stack, native controls and standard library before dependencies.
Small complete changes include failures, cancellation, retries and navigation.
Instructions and simulated outputs are not observations of the world.
Scale process to risk: a one-file automation needs a purpose, a check and a handoff;
a multi-tenant SaaS additionally needs isolation, migration and release evidence.
No rule requires empty documents, speculative abstractions or mandatory agents.
